# exam prep 审核规范评审及落实

已按下列评审更新项目skill至2.3.0，保留原文依据、双语一致性、独立盲答、真实题型及既有防猜题检查。新增考点覆盖和版本证据流程，并消除授权、格式及审核模式之间的冲突。

原评审对象为项目skill 2.2.0，依据题库 `b5ad1dc` 的覆盖审核及用户的实际考试反馈。2026年10月18日落实为 [skill 2.3.0](../../.claude/skills/exam-prep/SKILL.md)；以下保留原问题及建议以便核对。补题另见[覆盖报告](README.md)。通用skill的调整不改变 [本项目已定规则](../FORMAT.md)。

## 已落实的变更

| 范围 | 2.3.0处理 |
|---|---|
| 五项优先修改 | 增加来源先行的Coverage audit模式；将引文命中与语义支持分开；明确格式重排、选项重算和all/none语义；只报告审核不改原对象；将排除决定与正面范围一起检查。 |
| 名词与角色 | 从来源拆出性质、目的、职责、权限和易混身份；背景出现、解释提及与直接测试分开；不同法定主体不可仅因措辞相近而互相替代。 |
| 图页与版本 | 图表和扫描页须看原图，人工转录记录页码、语言及源文件版本并由另一人核对；保留审核基线、后续改动和最终盲答对应文本。 |
| 减少重复工作 | 复用用户已定范围和授权；跨来源缺口合并；只补残余内容；报告清单完成的具体范围。 |
| 风险与成本 | 独立双语盲答、原文语义及项目硬检查仍必需；不同模型对抗、嵌入及深入模拟按变化、风险和工具选择，不能把未运行写成通过。 |
| 历史成绩 | 题意、真假值或选项集合改变，即使选项数量相同也须版本处理；可新ID替代并保留旧成绩，不得静默重算。 |
| 重复及文体 | 区分重复命题与不同法定主体；支持有来源的职责边界比较；项目更严格的去重和格式规则继续优先。 |
| 文件结构 | 条件性的guard目录及环境／参考工具移入references并从主文件链接；不另建旧版skill副本。历史测量明示为示例，不当当前题库结论。 |

验证包括skill格式检查及另一审核者对实际情境的行为复核。完整证据随[最终补题实施记录](remaining-implementation.json)保存。本次没有放宽本项目的任何既有自动质量检查。

## 优先修改

| 建议 | 现状与具体证据 | 建议做法 | 收益及代价 |
|---|---|---|---|
| 增加独立的考点覆盖审核模式 | Audit 模式主要指向答案盲审与防猜题；Phase 3 把题目对应来源单位列为可选。此次23份资料均有引用，仍存在未直接测试的条件、例外及附件内容。 | 先从来源建立考点清单，再对应具体题句。分为已覆盖、部分覆盖、未覆盖、参考或范围外。记录主要单元、跨单元证据、遗漏部分及优先级。 | 减少漏考和无效扩题；初次要整理一份结构化清单，后续可以增量更新。 |
| 把“引用真实”与“答案受到支持”分开 | Phase 3 的措辞称引文检查能证明每个答案有依据，Guard catalogue 又把引文命中视作阻止来源不支持。`m3-261`第3句的地址绝对要求说明，原文命中仍可能漏掉同条的替代选项和例外。 | 自动检查只确认来源身份、位置和文字命中。语义审核另查主体、适用范围、条件、例外、并列/择一关系及跨条文引用。对真句主动找能推翻它的合规情形。 | 对减少错键最有价值；需对新增或变更题做有边界的原文阅读。 |
| 统一格式规则的适用条件 | 通用 guard 写“打乱格式不能有 all/none”；本项目已采用重排题句并重新映射选项，允许“以上皆是/皆非”固定在末项。示例规格仍偏向旧固定组合。 | 按格式声明“重排对象、选项如何重算、全选/全不选如何解释、官方样题是否逐字保留”。明示已确定的项目规则优先于通用默认。 | 避免把有效题型误判为错误；主要是文档整理，不必改现行题库。 |
| 消除“只报告”与“顺手修复”的冲突 | Audit 模式要求未获修复指令时只报告；Working with the owner 又要求小问题当场修复。 | 将“修复所见问题”限定在已获授权的修复模式。覆盖审核只记录发现与建议，修复和出题另有明确范围。 | 避免审核中改变被审核对象，结论更可复核；几乎没有额外成本。 |
| 把已决定的排除范围纳入检查 | 冲突登记E25说咨询回应日期不是考试内容，但`m1-142`第5句仍测试已过截止日期及抄送邮箱。 | 将“应教什么”和“不应出什么”都记录为可引用的决定。出题或改题时标注适用决定，覆盖审核同时检查遗漏与范围外内容。 | 避免继续增加低价值记忆题；需要一次整理既有排除决定。 |

## 值得增加

| 建议 | 本次看到的需要 | 实施边界 |
|---|---|---|
| 图表与扫描页的审核账目 | 定期申报通函15的文字提取缺少截图内部分填报字段。 | 记录哪些页面含图、哪些已看原页、哪些尚未能读取。不能用“文字搜索无结果”证明原文没有该点。 |
| 保留审核快照及证据位置 | 更新题库后，原本第3句可能换了意思；旧报告不能自动继续有效。 | 保存题库、引文、来源文本与决定文件的版本或摘要值；证据指向题目ID、当时句序及文本。报告标注何时应重新生成。 |
| 跨来源合并补题 | 实益拥有人、政治人物、中介人义务同时出现在条例、指引和FAQ。 | 每份资料都保留映射，但同一缺口只生成一个补题任务。区分全库已有覆盖与某单元尚无对应练习。 |
| 规则变化后的练习记录处理 | 现有 skill 提醒选项数量变化会破坏记录，但同样数量下改真值、选项集合或题意也可能使旧答案失真。 | 给影响评分的内容建立版本标记；变化时保留历史成绩并标注旧版，或使相关旧作答失效。不要只比较选项数量。 |
| 更明确的审核结论用语 | “测试通过”“已盲审”“已覆盖”分别证明不同事情。 | 每次报告写清范围、样本、比较对象和未做事项。覆盖率只能是已定义考点清单的比例，不能称为真实考试覆盖率或通过概率。 |
| 名词及机构职能专项 | 用户在实际考试中遇到机构职能问题。基线题`m1-134`已测FATF标准制定和评估跟进，当时全球合作网络与成员交流仍有缺口，现已补入`m1-152`；JFIU职责则分散在单元5、7。 | 按“名称/性质、目的、具体职能、权力边界、易混机构”逐项映射。区分实质缺口、已有但练习较少、归档来源不足；不能凭机构名称出现次数判断覆盖，也不能凭常识补写职能。 |

进一步检查整类名词与职责后，建议把这一步写成固定流程：**先从来源列对象，拆出定义条件和职能，再映射实际题句**。分别记录直接测试、仅在题干背景出现、只在解释／引文出现。相似定义也要核对适用对象，例如持牌人的最终拥有人与客户的实益拥有人，不能互相充当完整覆盖。跨来源的同一缺口合并为一个工作包；已知错误题句不得用来证明覆盖。详见[专项检查](TERMS-AND-ROLES.md)。

## 建议减少或改成按需要启用

| 现有规则 | 调整建议 | 代价与取舍 |
|---|---|---|
| 每次都重新询问所有规格；每个下载都单独征求同意 | 先读取用户已定范围和决定。范围内、已授权的常规资料读取和下载继续执行；新增来源、冲突或实质范围改变再询问。 | 减少重复确认，仍保留实质决定由用户作出的原则。 |
| 每个任务都运行不同模型家族对抗、跨语言嵌入及大量模拟 | 分成基础检查、按风险触发检查和可选深入检查。新题盲答与改动相关原文核对属于基础；模型对抗和嵌入按题量、变化及可用工具决定。 | 节省时间和成本；未运行的深入检查要明确说明，不能暗示已通过。 |
| 每项度量都必须变成测试；固定比例直接卡住所有考试 | 只把稳定、可重复且能明确判错的规则做硬检查。文体比例等作为诊断信号，阈值按格式与已判断样本校准。不得为了通过统计比例而破坏原文含义。 | 减少误报和迎合测试；需要保留人工判断及校准说明。 |
| 不允许同一知识点在不同地方重复出现 | 通用 skill 区分复制题句、泄露答案的互为正反题与有教学价值的不同情境。复习次数与题目独立性分开管理。 | 可支持渐进练习；本项目的严格去重决定仍有效，改变前须单独决定。 |
| Phase 4 一概排除 who-is-who tables | 改为排除没有考试依据的机构名录；保留有来源、有实质区别的“谁负责什么”对照。用户已明确要求检查机构职能，不应被这条默认文体规则挡住。 | 更符合本次学习需要；机构表须写职责和边界，不能只列缩写，也不凭空扩展官方资料范围。 |
| 长篇历史成绩、模型品牌比较、工具目录与操作步骤混在主流程 | 主文件保留工作模式、必需产物、验收条件和停止条件。把历史测量、环境问题及工具示例移到引用文档。 | 主规则更易维护，减少把历史测量当当前结论；迁移时须保留链接与版本。 |

## 建议的主流程

1. 读取既有考试规则、资料范围与冲突决定，只确认真正缺失的决定。
2. 建立来源及考点清单，记录范围外内容和图表读取情况。
3. 进行覆盖映射，合并同义缺口，按重要性确定补题顺序。
4. 按需要编写或修复题目，同时提供逐句解释、原文证据和适用条件。
5. 对新增或变更内容独立盲答，检查双语、例外和已定冲突处理，再运行适用的自动检查。
6. 检查应用流程与旧记录兼容性；发布前核对来源版本并重建产物。

建议先落实前表的五项优先修改，再逐步拆分主文件。保留既有严格审核的价值，但让每次任务的检查范围和完成条件更清楚。
