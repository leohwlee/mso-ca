## Purpose and reader

Ask how and where the learner will read: closed or open book, on a phone on the
train or at a desk, weeks or days before the exam, in which language. The
defaults below came from an owner memorising for a closed-book exam with a
fortnight left; adjust them to yours.

The notes exist so the learner recognises a situation and recalls the rule. They
are not an index to the source, a summary of every clause, or a rewrite of the
question bank.

**Source first, bank never.** Write from the sources and the checklist. The
reference project's notes were at one point assembled from the bank's
explanations and organised around questions and true/false ledgers; a bank
covers only what it happens to test, in wording shaped by its distractors, and
the notes were rewritten from the sources. After authoring, compare the notes
with the bank to find gaps, then go back to the source to fill them.

## Structure

- One page (or chapter) per exam section, in the exam's order and under its own
  titles, unless the owner prefers the sources' structure. Name on each page the
  sources it draws on.
- Within a page, topics follow the source's logic; keep together what the source
  keeps together.
- A heading states the situation or the plain rule ("Staff reports go straight
  to the reporting officer, unfiltered"), never a clause number ("¶7.13 says…").
  The citation trails as support.
- Keep the page outline in view (a contents list), and give every topic an
  anchor so questions can link to it.

## Forms by content

Choose the form by what the content is, in this order of preference:

| Content | Form |
|---|---|
| A process, a sequence of steps, an escalation | A flow, with the actor on each step and the time limit on each arrow |
| Rules that change with the situation | A table whose rows are the situations and whose columns are what applies |
| Numbers, amounts, shares, periods, fees, penalties | A table: the number, what it governs, when it starts or applies, what follows if it is missed |
| A list in the source | A card showing the list's name, its count ("four measures") and every member; flag the plausible items that are *not* on it where the exam uses them |
| Two or more easily confused things (bodies, thresholds, duties, terms) | Side by side, on the same dimensions |
| Who does what | A table of actors against duties and powers, with the boundaries |
| A timeline (renewals, deadlines counted from different events) | A line or track per clock, each with its starting event |
| Definitions | The term, the definition in the source's words, and what it excludes |
| Everything else | Short paragraphs; bullets last |

Draw the relationship the source states. Overlapping cases are a set of cases,
not a decision tree; a tree is right only when the source's logic really
branches. Show nested AND/OR conditions explicitly.

## Tiers and traps

- **Tier every block**: *Remember* (lists, numbers, names to recall exactly),
  *Understand* (reasoning, conditions, how parts interact), *Recognise* (enough to
  spot it among options), *Reference* (context, background, other sectors). The
  learner filters to "Remember" the night before.
- **Traps where they arise**: a callout beside the rule it protects, saying what
  the trap is and what the source says. Draw them from the owner's conflict
  rulings, the near-identical names and numbers, and the trap kinds the exam
  uses. A trap list collected on a separate page is read once and forgotten.
  Write the callout from the source ("carotenoids *mainly* absorb blue-violet
  light: the source does not say *only*"), never by copying the bank's false
  statements: notes that list the paper's traps turn practice into recognition.
- **Rulings visible but quiet.** Where a point applies one of the owner's conflict
  rulings, a small mark can link to the ruling, hidden until switched on, so the
  plain reading view stays plain.

## Figures

- Colour and shape carry a stated meaning, keyed beside the figure, or are not
  used. One set of kinds serves the whole pack (a duty or deadline, a discretion
  someone else holds, a safe outcome, an end state, background), and a shape keeps
  one meaning.
- The paragraph above a figure says how to read it, not what the page is about.
- Draw each figure once per language view; keep the source's terms from breaking
  across lines.
- Every page shows its key content visually, but a figure that adds nothing to a
  two-row table is clutter.

## Accuracy

- Every sentence grounded, every table cell cited, with the actual file name or
  document number and a locator.
- Keep conditions, qualifiers and modal strength exactly: *must*, *should* and
  *may* are different rules.
- Never present an invented example, number or list as the source's. Label
  worked examples as examples.
- Before writing a point, search what other pages already say and link rather
  than repeat.
- Date what is dated: a risk assessment's findings belong to its year; a list
  that changes (sanctions, watchlists) is the edition you archived.
- Counts are not coverage. Report "75 topics, 626 point pairs", never "complete".

## Languages

- One language per view, and a combined view if the owner reads both.
- Each view follows its own edition. A point found in one edition only appears
  in that view only. No page compares the editions.
- Where an edition is missing, a labelled study translation cites the original.

## Aids that earned their place

In the reference project the owner kept, and asked for, aids that changed how the
existing content is read:

- a **tier filter** (All; Remember and Understand; Remember only);
- a **numbers page**: every amount, share and period in one table, each with its
  condition or starting point and a link to its section;
- **list cards with counts**, and **comparison tables** for confused pairs;
- **deep links** from each question's explanation to its notes section;
- a **wrong-answer book** in the practice app;
- **ruling marks** linked to the decisions register, hidden by default.

## What to leave out

The same owner removed, after trying them: a per-part quick sheet of 60 facts
(it only restated the tiers and figures), a statement-by-statement drill mode,
hidden-answer study modes, oversized controls, a print button, a search box,
sample metadata, an introductory scope panel and a closing source summary. The
general lessons:

- Do not add another layer of prose that restates existing structure.
- Keep content visible; recall belongs in the practice app or an explicit recall
  mode, not in hidden text.
- Practice belongs in the bank, not in the notes.
- No standalone section-by-section listings or unsupported directories of
  institutions; a cited comparison of functions and powers is different and
  welcome.
- No opening paragraph that repeats the page overview.
- Ask before adding a feature; record removed ones in the register and do not
  re-propose them in the same form.

## Flashcards and other forms

- **Flashcards** from the same cited rules: the situation on the front, the rule,
  its condition and the citation on the back. Keep each card's id stable across
  rebuilds so re-imports update cards.
- **A recall mode** that blurs outcomes, numbers and penalties until clicked turns
  reading into self-testing.
- **A study plan** only when asked: sections by priority and source volume, with
  practice papers spaced across the remaining days.
- **Copy and product material**: a fact sheet per product (what it is, who it is
  for, the figures, the conditions and exclusions, what staff must never promise)
  usually beats prose.

## Checking the pages

Check every page three ways:

1. **Mechanically**: `scripts/notes_check.py` — every block cited, tiers valid,
   anchors resolve, ids unique, every language present in each bilingual block.
2. **Visually**: render every figure and look at it for overlaps, clipping,
   arrows crossing text and colours that mean nothing.
3. **At real widths**: desktop and phone, in every language view. Open the file
   directly; if a browser needs a server, serve only the output folder on a free
   port, never a folder that holds anything else. In the
   reference project, one review covered seven parts in three language modes at
   five widths (105 page cases).

## The notes template

`assets/notes-template.html` is one self-contained page: no external fonts or
scripts, light and dark themes, a contents list built from the headings, a tier
filter, a language switch (when the page has more than one language), a recall
mode and print styles. Copy it, set the title, and replace the example content
inside `<main>`. Its components:

| Component | Markup |
|---|---|
| Section (one topic) | `<section id="topic-anchor"><h2>…</h2> … </section>` |
| Block with tier and citation | `<div class="block" data-tier="remember"> … <p class="cite">Doc 03 ¶4.2</p></div>` (tiers: `remember`, `understand`, `recognise`, `reference`) |
| Language spans | `<span lang="en">…</span><span lang="zh-Hant">…</span>` inside any element; the switch shows one, both or the other |
| Trap callout | `<aside class="trap"><strong>Trap</strong> …</aside>` |
| Ruling mark | `<a class="ruling" href="#rulings-B4">B4</a>` |
| List card | `<div class="listcard"><h4>Customer due diligence measures <span class="count">4</span></h4><ol>…</ol><p class="notlisted">Not on the list: …</p></div>` |
| Comparison / situation table | `<table class="compare">` with a header row; first column the situation or the thing compared |
| Numbers table | `<table class="numbers">`: number, what it governs, when it starts, what follows |
| Flow | `<ol class="flow"><li><b>Actor</b> step <em>time limit</em></li>…</ol>` |
| Timeline | `<ol class="timeline"><li data-when="90 days before">…</li>…</ol>` |
| Recall target | `<span class="recall">HK$120,000</span>` (blurred in recall mode) |

`notes_check.py` reads these conventions; keep them if you restyle the page.
